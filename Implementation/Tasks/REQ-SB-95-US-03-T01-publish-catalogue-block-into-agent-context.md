# REQ-SB-95-US-03-T01 — Catalogue Publication Into Agent Context

## Parent Story

- Story: [[REQ-SB-95-US-03]] — `../UserStories/REQ-SB-95-US-03-published-catalogue-and-call-enforcement.md`
- Requirement: `Documentation/PRD.md` → REQ-SB-95 *An Agent Can Only Do What the App Can Do — Operator Profile, Actions, Workflows, Entity Resolution*

---

## Objective

Tell every agent exactly what this app can do, derived from the live catalogue —
a third auto-generated, marker-delimited block in its own SOUL.md, regenerated
by `ActionManager` on every catalogue change, never hand-edited.

---

## Starting State → End State

**Before / Inputs:**

- `app/business/core/agents/agent_manager.py` already owns two auto-generated
  blocks with exactly this idempotent replace-own-block shape (read directly):
  `_SPECIALISTS_BEGIN` / `_SPECIALISTS_END` and `_INDEX_GUIDANCE_BEGIN` /
  `_INDEX_GUIDANCE_END`, each marked "auto-generated by AgentManager -- do not
  hand-edit", each found by `prompt.find(BEGIN)` / `find(END)` and replaced in
  place.
- `SkillManager` calls `publish_section_access_map()` on every deploy/undeploy —
  the derived-republish trigger precedent.
- Nothing publishes anything about Actions.

**After / Outputs:**

- A third marker pair in `AgentManager` and a generator that emits, for ONE
  agent, only the Actions whose `allowed_callers` include that agent's id (or
  are `["*"]`), each with its id, description, inputs with required flags, and
  the one way to call it.
- The block is **removed entirely** when an agent may call nothing — no empty
  shell.
- Regeneration is triggered by the catalogue: `ActionManager.create()` /
  `update()` / `delete()` republish for every affected agent, the way
  `SkillManager` republishes the section-access map.
- Re-running publication is idempotent: the block is replaced between its own
  markers, never appended, and the agent's hand-authored prompt/guardrails/scope
  text around it is byte-identical afterwards.

## Constraints

- Inherits from parent story.
- **Publication is derived, never hand-copied.** No agent's stored prompt text
  may be mutated to carry a hand-written copy of the catalogue.
- `ADR-033`: this is the derived-republish *pattern*, **not** a second JSON
  file. Do not write an `action_catalogue.json` and do not touch
  `section_access.json`.
- **The gate never reads this text** (`REQ-SB-95-US-03-T02` reads the live
  catalogue), so a stale block can mislead an agent but can never let a call
  through. Do not wire the gate to the published block.
- `REQ-SB-33-US-01`'s global honest-uncertainty instruction stays exactly where
  it is — this is not a second instruction beside it.
- Existing agent behaviour is otherwise unchanged: ordinary conversation,
  memory, routing and Skills keep working as they do.

## Tests

**Automated tests** — `src/backend/tests/test_action_catalogue_publication.py`,
run with `pytest tests/test_action_catalogue_publication.py` from `src/backend`;
follow `tests/test_soul_and_profile_hygiene.py`'s existing technique for
exercising SOUL text.

1. `[REQ-SB-95-US-03-AC-01]` With three Actions of which two permit agent `A`
   (one by explicit id, one by `["*"]`), compose `A`'s SOUL text; assert the
   block is present between its markers, lists exactly those two Action ids with
   their descriptions, inputs and required flags and the one way to call them,
   and names nothing else.
2. `[REQ-SB-95-US-03-AC-01]` Compose the SOUL text of an agent permitted to call
   nothing; assert neither marker appears at all.
3. `[REQ-SB-95-US-03-AC-08]` Publish, then change the catalogue (add, edit,
   delete one Action) and publish again; assert exactly one marker pair exists,
   the block's content reflects the change, and the text outside the markers is
   byte-identical to before.
4. `[REQ-SB-95-US-03-AC-08]` Assert `ActionManager.create()` / `update()` /
   `delete()` each trigger republication (spy on the publish function) — no
   caller has to remember to.
5. `[REQ-SB-95-US-03-AC-08]` Delete an Action and assert it is absent from the
   regenerated block for every agent that previously listed it.

**Manual verification steps:**

1. `[REQ-SB-95-US-03-AC-01]` With the backend running and real Actions saved,
   open a real chat with an agent permitted to call some of them and ask what it
   can do; confirm every operation it names is a real catalogued Action from its
   own block, and that it names none that is not. Record the reply verbatim in
   the Implementation Log.
2. `[REQ-SB-95-US-03-AC-08]` Edit one Action in the catalogue, start a new
   conversation with the same agent, and confirm the change is reflected with no
   hand edit to the agent's prompt, guardrails or scope text.

> On test failure: read the error, fix the root cause, re-run. After 3 attempts,
> stop and report the failure to the user.
