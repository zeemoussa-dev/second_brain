Agent Activity

A chronological record of what background agent runs have happened — email, meeting, and (once built) to-do capture — with whether each succeeded or failed, plus whether Outlook is currently reachable, so a real capture failure is visible in the UI itself instead of only discoverable by symptom-chasing or digging through server logs (REQ-SB-11).

Not the same as System Health, which is a current-snapshot status board (is each piece healthy right now) — this page is the history/log of individual runs over time. It does not repeat System Health's own MCP-mount, Provider-availability, or last-capture-run checks.

Both the run list and the Outlook status below recompute fresh on open or refresh — the same "never a cached snapshot" convention already established for My Day's rolling window and System Health, not a stale result from an earlier page load.

Activity log

Every completed background capture run, across every configured capture agent, newest first. Scope: completed run_event (success) and failure outcomes only — chat messages and Supervised-mode pending-approval proposals are shown elsewhere (each agent's own Communication History on Agents Map; Pending Approvals) and are not duplicated here.

Every configured capture agent's runs appear here, not only some of them (Scenario 3) — Email Capture and Meeting Capture both show above. A failed run (Meeting Capture, 08:00) is listed with its own error detail, not silently dropped (Scenario 2) — depends on this story's own T01 fix (every capture pipeline's top-level entry point funnels an escaping exception into a recorded failed-run entry, the same honest-failure-funnel pattern already used for the chat path).

Communication channels

Reported honestly as direct Outlook COM reachability — not a "Hermes-wrapped" channel, since no live Hermes connection exists in this codebase yet. Reuses the same connection mechanism every existing Outlook read (mail, calendar) already relies on (outlook_com.py::_connect_namespace), attempted here purely as a reachability check — one new, lightweight, local, zero-external-cost call, no polling loop.
