# Capture Notes

**Quick and dirty, by design (operator, 2026-08-22).** This is the catch-all
for anything relayed to you that isn't a specific request another specialist
owns -- a passing thought, something overheard, a transcribed voice note, a
reminder. Your only job is to get it written down fast. Never ask a
clarifying question, never resolve or validate a Customer/Partner, never
block. A note that's filed immediately beats a perfectly-classified one that
took two minutes of back-and-forth to get there.

## Prerequisites

- Vault path (pass as `--vault-path` on every script call):
  `$SECOND_BRAIN_VAULT_PATH`

## What this builds

```
Work/Notes/<YYYY-MM-DD>/<Auto-Generated Title>.md
```

One folder per day, one file per note, under `Work/` -- deliberately NOT
filed under any Customer or Partner (operator's own explicit choice,
2026-08-22: "General Notes will Stay General for now... we will work on it
later" -- a future pass will reason over these and re-classify/re-file
them; this Skill's job is capture, not classification). Each note's own
file: frontmatter, then `## Summary`, then `## Body`.

## Job: Capture

Triggered by anything relayed to you -- there is no conversational flow to
run first, but there IS a small amount of real work before the script call:
**you generate the title and summary yourself** (the script is purely
mechanical and doesn't understand the content):

- **Title**: a short, honest label for what this is about (a few words) --
  becomes the filename. If nothing sensible suggests itself, it's fine to
  fall back to something generic like "Quick Note".
- **Summary**: one or two plain sentences of what this note is / why it
  matters -- your own genuine understanding, not a restatement of the body.
- **Body**: the content you were given, **verbatim** -- don't paraphrase,
  trim, or clean it up. If it arrived as a transcribed voice note, the
  transcription IS the body.

`write_file` a scratch JSON payload `{"title": ..., "summary": ...,
"body": ...}`, then call the script as a PLAIN, direct `terminal` call
using its own full absolute path:

```
terminal(command="python \"C:\\Users\\mahmoud.moussa\\AppData\\Local\\hermes\\profiles\\notes-manager\\skills\\notes-capture\\capture-notes\\scripts\\capture_note.py\" --input-file <scratch path>")
```

The script best-effort wikilinks any real Customer/Partner name it
recognizes in the summary/body (e.g. "called Adnoc" becomes "called
[[Adnoc]]") -- this is automatic, not something you need to do yourself, and
it's fine if it misses one. It also handles same-day title collisions on
its own. Report back briefly that it's logged; you don't need to narrate the
file path or the wikilinking.

## Pitfalls

- **Never ask what Customer/Partner this is about, and never hold the note
  back waiting for one.** That's the entire point of this Skill existing
  separately from `track-opportunities` -- Opportunities need a real
  Customer to file under; Notes don't.
- **Never wrap the script in `bash -lc "..."`** -- same categorical Hermes
  `terminal`-tool approval-block documented throughout this vault's Skills;
  a bare `python ...` command with the script's own full absolute path runs
  without a prompt.
- **The Body is verbatim, even though the Title and Summary are yours.**
  Don't reorganize the original content into bullet points or otherwise
  "clean it up" when writing the body -- your own editorial judgment goes
  into the title and summary only.

## Verification

- After a capture, confirm the returned `path` is a real file under today's
  `Work/Notes/<date>/` folder, and the Body matches what was actually sent
  (not paraphrased).
